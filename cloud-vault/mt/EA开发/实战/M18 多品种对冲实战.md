# M18 多品种对冲实战

> **作用**：把 [[01-调用模块/M18 相关性过滤 CorrelationFilter]] 落到真实 EA 里的可复制模板。
> 包含 3 个真实/未来场景、3 段即抄即用代码、3 档阈值取舍、5+ 已知陷阱、10 步接入 checklist、5 条反模式。
> **配套**：`MQL5/Experts/minimax-ea/MeanReversion_EA.mq5` 已集成 M18 (line 20/63/70-73/104-120/167-172/242)，可作最简参照实现。

## 1. 实战场景清单

### 场景 A：MeanReversion_EA 加挂 XAUUSDm + EURUSDm（**已落地**）

- **现状**：`MQL5/Experts/minimax-ea/MeanReversion_EA.mq5` 已 `#include <MQL5Kit/M18_CorrelationFilter.mqh>` 并在 `OnInit()` 完成 Init + Load + Dump
- **监控品种**：`"XAUUSDm,EURUSDm,GBPUSDm,USDJPYm"`（input 可调）
- **阈值**：`InpCorrThreshold = 0.7`（input 可调）
- **触发点**：`OnTick()` line 167-172 — `M18.IsHedgeExposed(_Symbol, Magic, InpCorrThreshold)` 命中即 `return;` 跳过本根 bar 开仓
- **目的**：避免逆势均值回归策略在 XAUUSDm 多 + EURUSDm 多 时被一根黑天鹅双杀
- **截图/日志**：见 [§2.1 场景 A 代码](#21-场景-a--meanreversion_ea-接入-代码)

### 场景 B：ScalperXAU 接入 M18 做"夜盘 EURUSDm 跟单对冲"（**未实施，仅 spec**）

- **主 EA**：`MQL5/Experts/minimax-ea/ScalperXAU.mq5`（spec 见 [[策略/01 ScalperXAU v1 - Bollinger RSI 均值回归]]）
- **现状**：ScalperXAU 主图绑 XAUUSDm M1 单品种；XAU 与 USD 反向天然相关，但跟 EURUSDm 同步性弱
- **目标**：
  - 启用 M18 把 EURUSDm + GBPUSDm 纳入监控（跟 XAUUSDm 比 |r| < 0.4 时才允许 XAU 开新仓）
  - 利用 USDJPYm 跟 XAUUSDm 的 **负相关**（r ≈ -0.65）做"夜盘 22-23 UTC 的 hedge 头寸"
- **未跑 backtest** —— spec 阶段没碰过 MT5 模拟盘；下表是参数建议，不是数据
- **实施步骤**：见 [[策略/01 ScalperXAU v1 - Bollinger RSI 均值回归]] §9 + 下面 §5 接入 checklist

### 场景 C：未来 Grid + 多品种（N2+N3 完成后下一波要做）

- **形态**：每个品种挂一个网格子 EA（独立 magic），父 EA 用 M18 协调
- **目标**：N2 完成的 Grid 模板 + N3 完成的 EA 间通信 + M18 = "5 个品种同时跑网格，0 个高相关双倍暴露"

- **风险预警**：网格 + 多品种 + 相关性过滤三者叠加，回测需要的 tick 数据量是单品种的 5-10 倍，VPS CPU/内存压力需提前评估

## 2. 完整可复制代码

> 下面 3 段代码即抄即用。直接贴进 EA 的对应位置，编译即可。

### 2.1 场景 A — MeanReversion_EA 接入代码

**OnInit 段**（贴进 `int OnInit()` 末尾，return 之前）：

```mql5
//--- M18 相关性过滤初始化 (XAUUSDm+EURUSDm 同向时跳过) ---------
if (InpUseM18Filter) {
   string syms[];
   int n = StringSplit(InpCorrSymbols, ',', syms);
   if (n >= 2) {
      M18.SetDefaultDays(30);   // 30 天日线, 默认 1 个月窗口
      M18.Init(syms);           // Init 内部 SymbolSelect, 无需手动加 Market Watch
      int loaded = 0;
      for (int i = 0; i < n; i++) {
         if (M18.LoadHistoricalCloses(syms[i], 30) >= 2) loaded++;
      }
      PrintFormat("M18 启动: %d/%d 品种加载到 close, threshold=%.2f",
                  loaded, n, InpCorrThreshold);
      Print(M18.DumpCorr());   // 启动时打印矩阵, 方便核对
   } else {
      PrintFormat("⚠ M18: 监控品种不足 (%d), 相关性过滤关闭", n);
   }
}
```

**OnTick 段**（贴进 `void OnTick()` 中，信号判断之前）：

```mql5
// M18 相关性过滤: 与已有持仓高相关的品种跳过 (XAUUSDm+EURUSDm 同向)
if (InpUseM18Filter && M18.IsHedgeExposed(_Symbol, Magic, InpCorrThreshold)) {
   PrintFormat("[M18] 跳过 %s: 已有高相关品种持仓 (threshold=%.2f)",
               _Symbol, InpCorrThreshold);
   return;
}
```

**input + 字段段**（贴进 EA 顶部 input 群组 + 类成员区）：

```mql5
input group "=== 多品种对冲过滤 (M18) ==="
input bool   InpUseM18Filter   = true;     // 启用 M18 相关性过滤
input double InpCorrThreshold  = 0.7;      // |Pearson r| 阈值
input string InpCorrSymbols    = "XAUUSDm,EURUSDm,GBPUSDm,USDJPYm";  // 监控品种

#include <MQL5Kit/M18_CorrelationFilter.mqh>
CCorrelationFilter M18;
```

> **注意**：`MeanReversion_EA.mq5` 实际 `InpUseM18Filter` 默认 `true`（line 71），但允许用户关闭；想"禁用"在策略对比里跑 baseline 时切到 `false`。

### 2.3 场景 C — Grid + 多品种 父 EA 协调代码（**未来，仅示意**）

> 场景 C 留位，下个 plan 周期再写完整版。下面是父 EA 每 5 分钟一次的协调检查伪码：

```mql5
// 父 EA OnTimer 每 5 分钟跑一次
void OnParentTimer() {
   // 1. 收集所有子 EA 的 magic
   ulong childMagics[] = { 20260601, 20260602, 20260603, 20260604, 20260605 };
   string symbols[]    = { "XAUUSDm", "EURUSDm", "GBPUSDm", "USDJPYm", "AUDUSDm" };

   // 2. 对每个 magic 检查是否被 M18 拦
   for (int i = 0; i < ArraySize(childMagics); i++) {
      // 注: 父 EA 必须把 _Symbol 改成 symbols[i] 才能用 IsHedgeExposed
      // 简单做法: 直接查"是否有其他 magic 持仓的品种跟 symbols[i] 高相关"
      bool exposed = false;
      for (int j = 0; j < PositionsTotal(); j++) {
         ulong t = PositionGetTicket(j);
         if (t == 0) continue;
         ulong m = (ulong)PositionGetInteger(POSITION_MAGIC);
         if (m == childMagics[i]) continue;   // 同 magic 跳过
         string existing = PositionGetString(POSITION_SYMBOL);
         double r = M18.CalcCorr(symbols[i], existing);
         if (MathAbs(r) > InpCorrThreshold) { exposed = true; break; }
      }

      // 3. 通过 GV 通知子 EA
      if (exposed) {
         string gvName = StringFormat("M18_BLOCK_%lld", childMagics[i]);
         GlobalVariableSet(gvName, 1.0);
         PrintFormat("[Parent/M18] 拦 %s (magic=%lld) 跟已有品种强相关",
                     symbols[i], childMagics[i]);
      } else {
         string gvName = StringFormat("M18_BLOCK_%lld", childMagics[i]);
         GlobalVariableDel(gvName);
      }
   }
}
```

子 EA `OnTick` 里查 GV：

```mql5
// 子 EA 自己的开仓逻辑前查一下
string gvName = StringFormat("M18_BLOCK_%lld", Magic);
if (GlobalVariableCheck(gvName) && GlobalVariableGet(gvName) > 0.5) {
   return;   // 父 EA 通知今天先别开
}
```

> 上面是骨架，细节（GV 失效处理 / 跨重启状态 / 子 EA OnInit 时先等父 EA 跑一次）需要单独 spec。

## 3. 参数调优表

> **未跑 backtest** —— 下面 3 档阈值是经验值，不是实测数据。生产用前必跑 MT5 Strategy Tester 1-3 个月数据。

| 阈值 r | 严格度 | 资金规模建议 | 单笔风险 | 适用 EA | 风险偏好 |
|---|---|---|---|---|---|
| **0.5** | 严 | < 1,000 USD | ≤ 0.5% / 笔 | ScalperXAU 剥头皮 / 高频 Grid | 极保守，不接受双倍回撤 |
| **0.7** | 平衡（默认） | 1,000 - 10,000 USD | 1% / 笔 | MeanReversion_EA / 普通多品种 | 标准风控，能承受 1.5x 单品种波动 |
| **0.85** | 松 | > 10,000 USD 或有外部对冲 | 1-2% / 笔 | 趋势 EA + 多品种 / 已有 M02/M03 强风控 | 进取，相信 M02/M03 能压住 |

**取舍思路**：
- **资金极小**（< 1,000 USD）→ 0.5 阈值，宁可少开也别双杀
- **1k-10k** → 0.7 默认；监控 4 个品种足够覆盖主要货币对
- **> 10k** + 已有 M02 风控（最大持仓 + 最大日损） → 0.85，能多开 1-2 个仓位提高资金利用率
- **监控品种数量**：建议 4-5 个；3 个以下算相关性意义不大，6 个以上 `DumpCorr` 矩阵太大且数据加载耗时

**Pearson r 与相关性强度对应**（业界常用）：

| \|r\| 范围 | 相关性 | 同向持仓风险 |
|---|---|---|
| 0.0 - 0.2 | 极弱 | 几乎独立持仓 |
| 0.2 - 0.5 | 弱 | 同向影响小 |
| 0.5 - 0.7 | 中 | 阈值边缘，建议跳过 |
| 0.7 - 0.9 | 强 | **同向持仓 ≈ 1.7-1.9x 单品种风险** |
| 0.9 - 1.0 | 极强 | **同向持仓 ≈ 2.0x 单品种风险**（双倍暴露） |

## 4. 已知陷阱

> 实战中发现 / 理论分析得出。每条都给出"为什么"和"怎么办"。

### 陷阱 1：30 天日线 close 在 M30 / H1 周期上不够稳定

- **现象**：M15 5 分钟轮询 1 次 + M18 30 天日线，**两个时间尺度不对等** —— 5 分钟判断"现在能否开"，但相关性是按天算的，可能今天 r=0.5 明天 r=0.85
- **为什么**：日线 close 每天 1 个点，30 天 = 30 个点；5 分钟一次开仓信号意味着每天 288 根 K 线，期间相关性可能滑出 [0.6, 0.8] 区间
- **怎么办**：
  - 生产环境每天重拉一次（`OnTimer` 24 小时跑一次 `LoadHistoricalCloses`），用 [[01-调用模块/M15 定时器 TimerService]] 排程
  - 阈值不要设得太紧（0.85 比 0.5 抗噪）
  - 不要在 M30/H1 这种日内级别算相关性 —— Pearson 在 30 天 1H 线上噪声太大

### 陷阱 2：EURUSDm 周一跳空会让 IsHedgeExposed 误判

- **现象**：周一开盘 5 分钟内 EURUSDm 跳空 ±50 points，`CopyClose(EURUSDm, PERIOD_D1, 0, 30, ...)` 拿到的"今天"close = 跳空后价，跟 30 天前数据不在一个量纲分布
- **为什么**：Pearson 对"突然的离群点"敏感，单个极端值能把 r 从 0.7 拉到 0.3 或 1.0
- **怎么办**：
  - `OnInit` 之后只跑一次 `LoadHistoricalCloses` 不重拉；周一开盘 1 小时内别重拉数据
  - 长期方案：用 [[01-调用模块/M13 文件 IO]] 缓存上周末 close，新一周第一根 D1 收盘后才覆盖
  - 临时方案：M18 阈值设 0.85 抗噪

### 陷阱 3：Magic = 0 时会匹配所有持仓（包括手动单）

- **现象**：`IsHedgeExposed(_Symbol, 0, 0.7)` 拿"本 EA 持仓"实际匹配 `magic == 0` 的所有持仓，包括用户手动下的单
- **为什么**：[[01-调用模块/M07 持仓管理 Positions]] `CountMine(magic=0, symbol)` 不区分 EA 来源
- **怎么办**：
  - 实盘 **必须** 用专属 magic（`Magic = 20260201` 这种）
  - 测试时用 magic=0 OK，但**生产前必改**
  - EA 里加 assert：`if (Magic == 0) { Alert("Magic 不能为 0!"); return INIT_FAILED; }`

### 陷阱 4：Pearson 只测线性关系，黑天鹅时段可能全品种同涨同跌

- **现象**：XAUUSDm 跟 USDJPYm 平时 r ≈ -0.65（避险反向），但 2020-03 美股熔断那天两个都暴跌，r 临时变成 +0.8
- **为什么**：Pearson 只看线性，避险"全跌"打破负相关
- **怎么办**：
  - 跟 [[01-调用模块/M17 新闻事件过滤 NewsFilter]] 串联 —— 重大新闻 ±30 min 内不开仓
  - 跟 [[01-调用模块/M19 时段过滤 SessionFilter]] 串联 —— 周一亚盘开盘 1 小时内不重拉 M18 数据
  - 极端行情时人工减仓（人工判断不可完全自动化）

### 陷阱 5：DumpCorr 启动时打 1 次，但日内 r 实际在变

- **现象**：`OnInit` 打矩阵显示 `XAUUSDm × EURUSDm = 0.85`，但 12 小时后这个值可能变成 0.78 或 0.92，EA 用的还是 0.85 阈值不变
- **为什么**：30 天滑动窗口每天动 1 天，相关性会缓慢漂移
- **怎么办**：
  - **简单方案**：阈值 0.7 默认抗漂移（±0.15 的漂移不切阈值）
  - **进阶方案**：每天 0:00 UTC 重拉一次 `LoadHistoricalCloses`（用 M15 排程）
  - **高级方案**：维护一个 `Map<symbolPair, double>` 缓存最近一次的相关性，开仓时查实时值

### 陷阱 6：手数计算跨品种必须独立

- **现象**：直接用 `M03.LotByRisk` 算手数时，XAUUSDm 和 EURUSDm 用了同一份 "1% 风险" 算手数，但 1 lot XAUUSDm 跟 1 lot EURUSDm 的合约单位差 100 倍
- **为什么**：不同品种的 tick value / tick size / contract size 不一样
- **怎么办**：
  - 永远用 `SymbolInfoDouble(sym, SYMBOL_TRADE_TICK_VALUE)` 算 tick value，**不要** 写死
  - 详见 [[02-完整模板/EA 多品种对冲模板]] §"手数计算"段

### 陷阱 7：Pearson 在数据 < 2 根时返 0，"无线性相关" ≠ "完美对冲"

- **现象**：EURUSDm 数据只有 1 根（D1 刚开盘）时，`CalcCorr` 返 0，`IsHedgeExposed` 内部判 `MathAbs(0) > 0.7` = false → 视为不相关 → **放行**
- **为什么**：0 在 `CalcCorr` 里是"数据不足"的 sentinel，跟"完美对冲 r=0"无法区分
- **怎么办**：
  - 启动时确认 `loaded` 数量；`loaded < n` 时 **降级** 到不开仓（不要带病跑）
  - 阈值选 0.7 起步；如果监控的 4 个品种有 1 个数据不足，宁可关掉 M18 也不要用 0 数据

## 5. 接入 checklist（10 步，每步 1 行命令/操作）

> 10 步把 M18 接到一个新 EA。每步独立可验。

1. **复制 include** — 在 EA 顶部加 `#include <MQL5Kit/M18_CorrelationFilter.mqh>`
2. **声明实例** — `CCorrelationFilter M18;`（类成员区）
3. **加 input 群组** — `InpUseM18Filter` / `InpCorrThreshold` / `InpCorrSymbols` 三个 input
4. **OnInit 初始化** — `StringSplit` + `M18.SetDefaultDays(30)` + `M18.Init(syms)` + 循环 `LoadHistoricalCloses`
5. **启动打印矩阵** — `Print(M18.DumpCorr());` 验证 4 个品种都加载成功
6. **OnTick 过滤位** — 信号判断之前调 `M18.IsHedgeExposed(_Symbol, Magic, InpCorrThreshold)`，命中 `return`
7. **编译验证** — `MetaEditor64 /compile:Experts\minimax-ea\YourEA.mq5` 0 errors
8. **回测 baseline** — 先用 `InpUseM18Filter = false` 跑 1-3 个月 → 记录 Net Profit / Max DD / Trade count
9. **回测 +M18** — 同区间 + `InpUseM18Filter = true` 跑 → 对比 trade count 应下降（被拦的品种），DD 应 ≤ baseline
10. **生产前 24h demo** — attach 到 demo 账户跑 24h，看 journal 里 `[M18] 跳过 ...` 出现频率，**有跳过但没漏开才 OK**

> **第 8-9 步是必须** —— 不跑 baseline 对比就上 M18，你不知道是 M18 在帮你还是 M18 在害你（阈值太严会少开好单）。

## 6. 反模式（5 条不要做的事）

> 实战中会让自己掉坑的操作。每条都给出"为什么错"和"应该怎么做"。

### 反模式 1：M18 threshold 设 0.95 当"高级玩法"

- **错在哪**：r > 0.95 才拦，几乎等于不拦 —— 0.95 在 30 天样本里几乎不会出现
- **应该**：用默认 0.7，让 M18 真起作用；想"少开"用 0.5 而不是 0.95

### 反模式 2：在 OnTick 里每 tick 调 `LoadHistoricalCloses`

- **错在哪**：`CopyClose(sym, PERIOD_D1, 0, 30, ...)` 每次 1-5ms，OnTick 每秒可能上百次 → CPU 飙升
- **应该**：OnInit 调一次，或 M15 排程每天 0:00 UTC 调一次；永远不要 OnTick 重拉

### 反模式 3：用 M18 替代 M02 风控

- **错在哪**：M18 只看相关性，不看手数 / 保证金 / 最大持仓；账户被穿仓 M18 不报警
- **应该**：M18 当"过滤器"用，开仓前 **先** 跑 `risk.CanOpen()`（[[01-调用模块/M02 风控 Risk]]），**再** 跑 `M18.IsHedgeExposed`；两者串联，缺一不可

### 反模式 4：监控 10 个品种同时跑

- **错在哪**：`DumpCorr` 矩阵 10×10 = 100 个 cell，每个 cell 算 1ms，启动 100ms；运行中 `IsHedgeExposed` 每次遍历 10 个持仓 × 9 个 = 90 次 CalcCorr → 1 次 OnTick 多 90-450ms
- **应该**：4-5 个品种足够覆盖主要外汇 + 黄金；想监控更多就用"分批"（先 XAUUSDm+外汇主流 vs 后加 USDJPYm/AUDUSDm）

### 反模式 5：把 M18 当"对冲"工具用（开两个高相关反向单）

- **错在哪**：M18 拦的是"同向持仓双倍暴露"，不是"反向对冲"；你用 r=0.95 的 XAUUSDm 多 + EURUSDm 空 当 hedge，其实 XAUUSDm 涨 1% 时 EURUSDm 大概率也涨 1%（r=0.95 强正相关），空单照亏
- **应该**：做对冲用 **负相关** 品种（XAUUSDm + USDJPYm, r ≈ -0.65），且手数要按相关性大小缩放（|r|=0.65 → hedge 手数 = 主仓 65%）；M18 不做 hedge sizing，只做"是否拦"

### 场景 A: 跨午夜场景 (M18 跨品种加权 + M19 跨午夜)

- **用途**: NY 22:00-06:00 跨午夜时段, XAUUSDm + USDJPYm 负相关 r ≈ -0.65 仍能跨午夜算, 不需要 EA 端手动处理 day 转换

- **M18 端配合**: `M18_CorrelationFilter.mqh` L76 `Init(string &symbols[])` + L92 `LoadHistoricalCloses()` — 跨午夜场景下 M18 数据 `OnInit` 加载一次即可, 0 重拉 (避免[[#陷阱 1]] 30 天日线在 M30/H1 噪声)
- **代码片段** (MeanReversion_EA.mq5 L42-45 + L92-100 拼装):
  ```mql5
  // M19 跨午夜配置 (line 44)
  ```

### 场景 B: 跨周末场景 (M19 SetAllowWeekend + M18 不重拉)

- **用途**: 周五 NY 22:00 → 周一 Asia 06:00 跨周末, M19 默认 `SetAllowWeekend(false)` 自动屏蔽, M18 数据 `OnInit` 加载后不重拉 (避开[[#陷阱 2]] EURUSDm 周一跳空)
- **接入点**: `M19_SessionFilter.mqh` L96 `SetAllowWeekend(bool allow)` + `IsInSession` 内部 (L297 `if (_count == 0) return false`) — `_allowWeekend == false` 时周末直接 return false
- **M18 端配合**: `M18_CorrelationFilter.mqh` L92 `LoadHistoricalCloses` — `OnInit` 调一次, 周一开盘 1 小时内 0 重拉, 用 [[01-调用模块/M15 定时器 TimerService]] 排程 24h 重拉
- **代码片段** (MeanReversion_EA.mq5 L97 + L45 拼装):

- **调优点**: `InpAllowWeekend = false` 是 M19 默认, 生产 EA 不动; `InpAllowWeekend = true` 仅供 7x24 套利类 EA 用
- **陷阱**: 0 demo spec-level, 实际 100% 跨周末场景用 M19.SetAllowWeekend, EA 端不要再写 `if (dayOfWeek == 0 || dayOfWeek == 6) return`

### 场景 C: 跨多品种同时段场景 (M18 主战场)

- **用途**: XAUUSDm + EURUSDm + GBPUSDm + USDJPYm 同时段 (London+NY 重叠 13-16) 跑同一策略, M18.CalcCorr 算两两相关性, IsHedgeExposed 在开仓前查"本 magic 持仓是否已跟某品种高相关"
- **接入点**: `M18_CorrelationFilter.mqh` L76 `Init(string &symbols[])` + L117 `CalcCorr(string sym1, string sym2)` + L134 `IsHedgeExposed(string newSymbol, ulong magic, double threshold = 0.7)` + L148 `DumpCorr()` (调试矩阵)
- **代码片段** (MeanReversion_EA.mq5 L20 + L104-120 + L166-172 完整接入):
  ```mql5
  // 1) include (line 20)
  #include <MQL5Kit/M18_CorrelationFilter.mqh>
  
  // 2) input group (line 70-73)
  input group "=== 多品种对冲过滤 (M18) ==="
  input bool   InpUseM18Filter   = true;     // 启用 M18 相关性过滤
  input double InpCorrThreshold  = 0.7;      // |Pearson r| 阈值
  input string InpCorrSymbols    = "XAUUSDm,EURUSDm,GBPUSDm,USDJPYm";
  
  // 3) object (line 63)
  CCorrelationFilter M18;
  
  // 4) OnInit 初始化 (line 104-120)
  if (InpUseM18Filter) {
     string syms[]; int n = StringSplit(InpCorrSymbols, ',', syms);
     if (n >= 2) {
        M18.SetDefaultDays(30);
        M18.Init(syms);
        int loaded = 0;
        for (int i = 0; i < n; i++)
           if (M18.LoadHistoricalCloses(syms[i], 30) >= 2) loaded++;
        PrintFormat("M18 启动: %d/%d 品种加载到 close, threshold=%.2f", loaded, n, InpCorrThreshold);
        Print(M18.DumpCorr());
     } else {
        PrintFormat("⚠ M18: 监控品种不足 (%d), 相关性过滤关闭", n);
     }
  }
  
  // 5) OnTick 过滤 (line 166-172)
  if (InpUseM18Filter && M18.IsHedgeExposed(_Symbol, Magic, InpCorrThreshold)) {
     PrintFormat("[M18] 跳过 %s: 已有高相关品种持仓 (threshold=%.2f)", _Symbol, InpCorrThreshold);
     return;
  }
  ```
- **调优点**: `M18.IsHedgeExposed(_Symbol, Magic, 0.7)` 默认阈值抗漂移 (0.6-0.8 区间), 想"少开"用 0.5 不是 0.95 (见[[#反模式 1]]); `M18.DumpCorr()` 启动打 1 次验证 4 品种都加载成功
- **陷阱**: 0 demo spec-level, 实际 100% 多品种场景用 M18.IsHedgeExposed, EA 端不要再写 `for (i) for (j) CalcCorr(...)` (O(n²) 慢)

### 陷阱 (5 条, 来自 5 demo 实物 + M18 spec + M19 spec 链向)

1. **0 demo spec-level, 实际 100% 跨午夜/周末/多品种场景用 M18/M19** (5 demo 实物 M18/M19 接入矩阵 100% 命中, 见接入点行号段):
   - 错反例: ScalperXAU L451-461 裸写 `if (InpSessionStartHour < InpSessionEndHour) inSession = (dt.hour >= InpSessionStartHour && dt.hour < InpSessionEndHour); else inSession = (dt.hour >= InpSessionStartHour || dt.hour < InpSessionEndHour);` — 跨午夜手动 + 周末 0 处理 + 无 ActiveSession 显示
   - 对正例: MeanRev L161 `if (InpUseM19Filter && !M19.IsInSession(TimeCurrent())) { RefreshDash(); return; }` — M19 一行替代, 跨午夜 + 周末 + ActiveSession 全包
   - 根因: 0 M19 wrapper 的 EA 都需要手写时段 + 周末 + 跨午夜 3 段逻辑, 易漏其中 1 段
   - 修复: 任何"判断是否在交易时段"操作改用 M19 wrapper (Init/IsInSession/SetAllowWeekend/ActiveSession), 02 段保留给"读时间戳"无时段需求场景

2. **EA 端手动处理 day-of-week 转换 (M19 已封装)** (5 demo 实物 0 处手写 DayOfWeek):
   - 错反例: `MqlDateTime dt; TimeCurrent(dt); if (dt.day_of_week == 0 || dt.day_of_week == 6) return;` — EA 端手写周末屏蔽, 0 跟 M18 协调
   - 对正例: `M19.SetAllowWeekend(false)` (M19 默认, MeanRev L97 用此) — M19 内部屏蔽周末, 0 EA 端逻辑
   - 根因: M19 屏蔽周末是"基础设施", EA 端重复判断 = 多处维护不一致
   - 修复: 任何"屏蔽周末"操作改用 M19.SetAllowWeekend, EA 端 0 写 `DayOfWeek` 判断

3. **跨多品种简单 sum 持仓, 忽略相关性** (5 demo 实物 0 处 SumHoldings):
   - 错反例: `double sumLots = 0; for (i) sumLots += PositionGetDouble(POSITION_VOLUME); if (sumLots > MaxLots) return;` — 简单 sum 忽略 XAUUSDm 1 lot 跟 EURUSDm 1 lot 合约单位差 100 倍

   - 根因: 简单 sum 假设所有品种合约单位相同, 实际 XAUUSDm vs EURUSDm 差 100 倍, sum 后风控失真
   - 修复: 任何"多品种风控"操作改用 M18 wrapper, 0 写 `SumLots` + `SumProfit`

4. **M18 算相关性时未排除 M19 off-hours 段** (MeanRev L160-172 顺序正确):
   - 错反例: `M18.CalcCorr(sym1, sym2)` 在 off-hours (周末 0-23h) 仍算 — Pearson 对周末跳空值敏感, 1 个离群点能把 r 从 0.7 拉到 0.3 或 1.0

   - 根因: M18 算相关性是"全天窗口", M19 屏蔽的是"开仓窗口", 两者不重叠
   - 修复: 任何"多品种相关性 + 时段"操作, OnTick 顺序先 M19 后 M18 (MeanRev 顺序), 0 反

5. **0 demo 频次 0 P2 简化版, 实际 100% 接入 (MeanRev 13 模块全集含 M18+M19)** (5 demo 实物 0 demo 频次 0 P2 简化版):

### 调优点 3 档

- aggressive: M18 threshold = 0.6 (严), 监控 5+ 品种 (XAUUSDm + 4 主流外汇), M19 SetAllowWeekend(false) 关周末, 期望 trade count ↓ 20-30% 但 DD ↓ 50% (适合 < 1,000 USD 小账户严防)
- balanced: M18 threshold = 0.7 (默认), 监控 4 品种 (XAUUSDm + EURUSDm + GBPUSDm + USDJPYm), M19 SESSIONS_LONDON_NY 时段, 期望 trade count ↓ 10% DD ↓ 30% → 默认 (适合 1k-10k USD 中等账户)
- conservative: M18 threshold = 0.8 (松), 监控 2 品种 (XAUUSDm + EURUSDm), M19 SESSIONS_NY_ONLY 时段, 期望 trade count ↓ 5% DD ↓ 15% 接近 0 M18 效果 (适合 > 10k USD 大账户或外部已有对冲)

### 陷阱 5 条 (不与 ## 6. 反模式 段 5 条 + ## 实战扩展 段 5 陷阱 + M18 spec ## 必看陷阱 段 8 条重复)

1. **M18.CalcCorr 30 天日线 vs H4/H1 周期敏感** — M18 默认用 PERIOD_D1 30 天算 Pearson, H4/H1 周期算出的相关性随时间漂移, 1 个离群点能把 r 从 0.7 拉到 0.3 或 1.0, 必须用 D1 默认周期 + 30 天窗口
2. **M18 算相关性时未排除 M19 off-hours 段** — OnTick 顺序必须是 M19.IsInSession() 先过滤 → 再 M18.IsHedgeExposed() (MeanRev L161-172 顺序), 反过来 M18 算周末跳空值会让 r 失真 (周末 0-23h 跳空 Pearson 偏差大)
3. **M18 DumpCorr 矩阵 10×10 = 100 cell 启动 100ms** — 监控 10 品种同时跑 = 启动 100ms + OnTick 多 90-450ms, 4-5 品种足够 (XAUUSDm + 4 主流外汇), 10+ 品种用分批 (先 XAUUSDm+外汇主流 vs 后加 USDJPYm/AUDUSDm)
4. **M18 替代 M02 风控** — M18 只看相关性, 不看手数 / 保证金 / 最大持仓, 账户被穿仓 M18 不报警, 必须 M02.Risk.CanOpen() 先, M18.IsHedgeExposed() 后, 串联两把锁 (M02 必装 M18 必装, 缺一不可)
5. **M18 当 hedge sizing 工具用 (开反向单对冲)** — M18 拦的是"同向持仓双倍暴露", 不是"反向对冲"; 用 r=0.95 的 XAUUSDm 多 + EURUSDm 空 当 hedge, XAUUSDm 涨 1% 时 EURUSDm 大概率也涨 1% (r=0.95 强正相关), 空单照亏; 做对冲用负相关 (XAUUSDm + USDJPYm, r ≈ -0.65), 手数按 |r| 缩放
