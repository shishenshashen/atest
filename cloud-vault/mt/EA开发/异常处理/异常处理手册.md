## §1 4 大异常维度

### §1.1 OrderSend retcode (M01 + M02, 12 个 retcode 码表)

**维度 1 范围**: M01 CTradePlus + M02 Risk。下单 / 平仓 / 改 SLTP / 挂单 / 删挂单 5 个交易动作的服务器端返回码。

**12 个 retcode 速查** (Node.js fs grep `[[01-调用模块/M01 交易封装 CTradePlus]]` `[[04-避坑与速查/02 OrderSend 错误码速查]]` L52-78 + L82-91 验证):

| retcode | 名称 (MQL5 官方) | 含义 | 处理 |
|---|---|---|---|
| **10004** | `TRADE_RETCODE_REQUOTE` | 重新报价 (要重试) | Refresh price + Sleep(100) + 重试 3 次 |
| **10006** | `TRADE_RETCODE_REJECT` | 请求被服务器拒绝 (参数错) | 必查 `res.comment` 找根因 (filling / magic / SL 距离) |
| **10007** | `TRADE_RETCODE_CANCEL` | 订单被交易者手动取消 | Skip, 不重试 |
| **10008** | `TRADE_RETCODE_PLACED` | 挂单已挂 (成功) | ✅ DONE 之一 |
| **10009** | `TRADE_RETCODE_DONE` | ✅ 完全成交 (成功) | ✅ DONE |
| **10010** | `TRADE_RETCODE_DONE_PARTIAL` | 部分成交 (成功但记录) | ✅ DONE 之一 |
| **10013** | `TRADE_RETCODE_INVALID` | 无效请求 (参数错) | 必查 `res.comment` (常见 filling 错) |
| **10014** | `TRADE_RETCODE_INVALID_PRICE` | 无效价格 (过期 / SL 距离错 / filling 错) | Refresh + 重新算 SL/TP + 重试 |
| **10015** | `TRADE_RETCODE_INVALID_STOPS` | SL/TP 距离过近 (≥ SYMBOL_TRADE_STOPS_LEVEL) | 重新算 SL/TP 距离 + 重试 |
| **10016** | `TRADE_RETCODE_INVALID_VOLUME` | 手数无效 (min/max/step 不符) | `LotByRisk` clamp + 重新算手数 |
| **10018** | `TRADE_RETCODE_MARKET_CLOSED` | 市场关闭 (周末/节日/维护) | M19 SessionFilter 预防, 不靠 OrderSend 撞 10018 |
| **10019** | `TRADE_RETCODE_PRICE_OFF` | 无报价 (broker 没推送) | Sleep(500) + Refresh + 重试 3 次 |

**重试策略** (M01 CTradePlus L82-100 + L73-77 `SetRetry` 内部已封装):
- **可重试 5 个**: 10004 REQUOTE / 10020 PRICE_CHANGED / 10019 PRICE_OFF / 10022 PRICE_EXPIRED / 10024 QUOTE_OFF
- **必查根因 4 个**: 10013 REJECT / 10014 INVALID_PRICE / 10018 MARKET_CLOSED / 10030 FREEZE
- **重试公式**: `SetRetry(3, 200)` = 最多 3 次, 间隔 200ms (剥头皮 100ms, 趋势 500ms)
- **重试间隔必须 ≥ 50ms** (避免 broker 限流 10032)

### §1.2 Indicator handle 失效 (M04, 3 种 fallback)

**维度 2 范围**: M04 IndicatorPool + 裸 `iMA/iRSI/iATR/iBands/iMACD/iStochastic/iADX` 句柄。

**3 种 fallback**:

1. **重新创建 (Recreate)**: handle = `INVALID_HANDLE` (== -1) 时, 重新调 `iMA(...)` 等创建函数, 替换 pool 里老 handle。`CIndicatorPool::_Add` 内部 (M04 L153-171) 已支持同名 handle 替换。
   ```mql5
   int h = ind.Get("MA_Fast");
   if (h == INVALID_HANDLE) {
      Print("MA_Fast handle 失效, 重新创建");
      ind.AddMA("MA_Fast", FastMA, MODE_EMA);   // recreate
   }
   ```

2. **退避重试 (Retry-with-backoff)**: 句柄暂时拿不到值 (broker 数据不足) 时, 指数退避重试 3 次 (100ms / 200ms / 500ms), 第 4 次仍失败 = 跳过本次。
   ```mql5
   for (int i = 0; i < 3; i++) {
      double val = ind.Value("RSI");
      if (val != EMPTY_VALUE) break;     // 拿到值
      Sleep(100 << i);                   // 100/200/400ms
   }
   if (val == EMPTY_VALUE) return;       // 跳过本次 K 线
   ```

3. **跳过本次 (Skip-tick)**: handle 失效 + 数据不足时, 不重试, 跳过本根 K 线。
   ```mql5
   double rsi = ind.Value("RSI");
   if (rsi == EMPTY_VALUE) return;   // MeanReversion_EA L153 范本
   ```

**EMPTY_VALUE 必查** (M04 spec L222 警告): `EMPTY_VALUE = DBL_MAX` (1.79e+308), 任何 `if (rsi > 70)` 漏检查 = 永远 true / 永远 false, 行为错乱。

### §1.3 文件 I/O 失败 (M13, 5 种 errno)

**维度 3 范围**: M13 FileIO + M11 Logger + M10 通知日志 + M12 GV。

**5 种 errno** (实测自 MT5 沙箱):

| errno | 名称 | 原因 | fallback |
|---|---|---|---|
| **2 (ENOENT)** | file not found | 文件不存在 | 首次创建 + 写表头 (CsvProto `_csvHeaderWritten = false` L57) |
| **13 (EACCES)** | access denied | 沙箱外路径 (C:\Windows\, C:\Program Files\) | fallback 到 `MQL5/Files/` 默认沙箱 (M13 L52-89) |
| **28 (ENOSPC)** | disk full | 磁盘满 | 写 Print 不写盘 + 通知用户 |
| **34 (ERANGE)** | path too long | `MQL5/Files/trades_2026_06_05_v2_5_EURUSD_XAUUSD.csv` 超 260 字符 | 简化文件名 (短日期 + symbol) |
| **32 (EBUSY)** | sharing violation | 多 EA 共享路径 + 缺 `FILE_SHARE_WRITE` flag | M13 spec L44 `FILE_SHARE_READ\|FILE_SHARE_WRITE` 都加 |

**fallback 优先级** (高→低): FileOpen CSV 写盘 → FileOpen TXT 追加 → Print 控制台 → Alert 弹窗 (慎用, 阻塞 EA)。

### §1.4 网络/连接失败 (M10 Notify + M17 NewsFilter, 3 种重试)

**维度 4 范围**: M10 Notify (SendNotification / SendMail / PlaySound) + M17 NewsFilter (LoadFromCSV 失败) + MT5 网络断线 (OrderSend 10031 CONNECTION)。

**3 种重试**:

1. **Exponential backoff (指数退避)**: `Sleep(100) → Sleep(200) → Sleep(400) → Sleep(800)` 第 4 次仍 fail = 放弃。
   ```mql5
   int delays[] = {100, 200, 400, 800};
   for (int i = 0; i < 4; i++) {
      if (SendNotification(msg)) break;     // 成功
      Sleep(delays[i]);                     // 退避
   }
   if (i == 4) Print("SendNotification 4 次失败");   // fallback 到 Print
   ```

2. **Circuit breaker (熔断)**: 连续 N 次失败 (N=10) 后, 暂停推送 5 分钟, 避免刷屏 + 给 broker 恢复时间。
   ```mql5
   static int _consecutiveFail = 0;
   static datetime _circuitOpen = 0;
   if (_consecutiveFail >= 10 && TimeCurrent() < _circuitOpen + 300) {
      return;   // 熔断中, 跳过推送
   }
   if (SendNotification(msg)) {
      _consecutiveFail = 0;
   } else {
      _consecutiveFail++;
      if (_consecutiveFail >= 10) _circuitOpen = TimeCurrent();
   }
   ```

3. **Graceful degradation (优雅降级)**: M10.Send 失败 → fallback 到 Print; M17.LoadFromCSV 失败 → fallback 到禁用新闻过滤 (不拦单); MT5 断线 → 跳过本根 K 线等下一根。
   ```mql5
   if (!news.LoadFromCSV(InpNewsCsvPath)) {
      PrintFormat("M17 CSV 加载失败, fallback 关闭新闻过滤: %s", news.LastError());
      InpUseNewsFilter = false;   // graceful degradation
   }
   ```

**3 种 fallback 输出** (从高到低): 1) `SendNotification` (Push 微信/Telegram) → 2) `SendMail` (邮件) → 3) `Print` 控制台 → 4) 静默 (不通知)。任意 1 个成功 = OK, 全部失败 = 走降级路径。

## §2 19 模块异常处理段位 (每模块 4-6 行紧凑版)

### M01 交易封装 CTradePlus — retcode 表 + 重试 3 次

- **关键 API**: `trade.Buy/Sell/ClosePos/ModifySLTP`, 内部 `SetRetry(3, 200)` 默认 3 次重试
- **fallback**: `_AutoSetFilling` 内部按 `SYMBOL_FILLING_MODE` 选 FOK/IOC/RETURN; `ClosePos` 10005 (已平) 视为成功

### M02 风控 Risk — 保证金不足 fallback

- **异常**: 客户端 134 (资金不足) / 持仓数超限 / SL 距离过近
- **关键 API**: `risk.CanOpen(type, lot, sl, tp)`, 7 项检查 (品种可交易 / 账户允许 / 手数边界 / 最大持仓 / 保证金占比 / 最小 SL 距离)
- **fallback**: 资金不足时降手数 (`sizing.LotByRisk` clamp 到 `SYMBOL_VOLUME_MAX`); 持仓数超限 Skip; SL 距离过近调整 SL
- **demo**: MeanReversion_EA L199 `risk.CanOpen` 串在 trade.Buy 前; ScalperXAU L771 同; MyEA L179 `if (!risk.CanOpen(...)) return;`

### M03 仓位计算 PositionSizing — 异常手数 clamp

- **异常**: `LotByRisk` 返 0 (SL=0 / RiskPct=0) 或超出 SYMBOL_VOLUME_MIN/MAX
- **关键 API**: `sizing.LotByRisk(RiskPct, slDist)`, clamp 到 `[minL, maxL]`, 按 `stepL` 量化
- **fallback**: `if (lot <= 0) return;` (MyEA L177 范本); 越界时降手数 (而不是直接拒单)
- **demo**: MeanReversion_EA L197 `sizing.LotByRisk`; MyEA L177; ScalperXAU L766

### M04 指标句柄管理 IndicatorPool — 失效 3 fallback

- **异常**: handle = `INVALID_HANDLE` (-1) / `EMPTY_VALUE` (DBL_MAX) / `CopyBuffer` 返 0 或 -1

### M05 新 K 线检测 NewBar — 异常 NewBar 跳过

- **异常**: NewBar 误判 (新 K 线检测失败 / 跨周末 / 节假日首根)
- **关键 API**: `NB.IsNewBar()`, 返回 true 才执行信号; 跨周末第一根 K 线 (周一 00:00) 必 IsNewBar() = true

## §6 5 反模式 (不与 80 ❌ baseline 重复)

> **承诺**: 本节 5 反模式不与 14 实物反模式 + 80 ❌ baseline + 5 速查 31+24=55 条重复。**新维度** = "异常处理本身的反模式" (不是"反异常处理的反模式")。

### 反模式 1: 吞掉错误 (try/catch 不 Print)

**错在哪**: 异常 try 起来 + catch 起来, 但不 Print, 后续 debug 完全不知道发生了什么。
**反例**:
```mql5
try {                                     // MQL5 不支持, 但思路是"接住"任何异常
   trade.Buy(lot, sl, tp, "x");
} catch (...) { /* 静默 */ }              // ❌ 吞掉, 无任何信息
```
**正例**:
```mql5
if (!trade.Buy(lot, sl, tp, "x")) {        // MQL5 用 retcode 检查代替 try
   PrintFormat("Buy fail: retcode=%d err=%d",
               trade.LastRetcode(), GetLastError());
}
```

### 反模式 2: 重试无退避 (立即 retry 1000 次)

**错在哪**: 失败立刻重试 1000 次, broker 限流 (retcode 10032) + 资源耗尽 (CPU 100%) + 用户以为"EA 卡死"。
**反例**:
```mql5
for (int i = 0; i < 1000; i++) {          // ❌ 1000 次立即重试
   if (trade.Buy(lot, sl, tp, "x")) break;
}
```
**正例**:
```mql5
for (int i = 0; i < 3; i++) {             // ✅ 最多 3 次 + 退避
   if (trade.Buy(lot, sl, tp, "x")) break;
   Sleep(100 << i);                        // 100/200/400ms
}
```

### 反模式 3: fallback 默认值 (magic=0 掩盖问题)

**错在哪**: 异常时 fallback 到默认值, 看起来"正常", 实际掩盖了根因。例: M01 失败 fallback 到 `SetExpertMagicNumber(0)` = 跟所有 EA 冲突。
**反例**:
```mql5
if (!trade.Buy(...)) {
   trade.SetExpertMagicNumber(0);          // ❌ fallback 0 = 跟所有 EA 冲突
   trade.Buy(lot, sl, tp, "x");
}
```
**正例**:
```mql5
if (!trade.Buy(...)) {
   PrintFormat("Buy fail, 根因: %s, 不掩盖, 人工介入",
               trade.LastComment());
   M10.Alert("Buy 失败, 根因=" + trade.LastComment());
   return;                                 // ✅ 不掩盖, 通知用户
}
```

### 反模式 4: 异常当正常 (return != SUCCESS 当成功)

**错在哪**: `return != SUCCESS` 当"成功"处理, 后续逻辑错位。例: `if (trade.Buy()) OpenNewPosition();` 实际 Buy 返 true 但 retcode=10018 MARKET_CLOSED = 仓位没开。
**反例**:
```mql5
if (trade.Buy(lot, sl, tp, "x")) {        // ❌ Buy 返 true 不代表 DONE
   OpenNewPosition();                      // 仓位没开就 OpenNewPosition 错位
}
```
**正例**:
```mql5
if (trade.Buy(lot, sl, tp, "x") &&        // ✅ 检查 retcode
    trade.LastRetcode() == TRADE_RETCODE_DONE) {
   OpenNewPosition();
}
```

### 反模式 5: 静默失败 (retcode 10004 不通知)

**错在哪**: 10004 REQUOTE / 10006 REJECT 等异常发生时, 不发 M10.Notify, 用户完全不知道 EA 失败了。
**反例**:
```mql5
if (res.retcode == 10004) {
   Print("REQUOTE");                      // ❌ Print 不发 M10, 用户无感知
}
```
**正例**:
```mql5
if (res.retcode == 10004) {
   M10.Send(StringFormat("⚠ REQUOTE x%d: %s", _requoteCount, res.comment), true);
   // ✅ M10.Send 发 Push + 邮件 + 声音, 用户立即知道
}
```
