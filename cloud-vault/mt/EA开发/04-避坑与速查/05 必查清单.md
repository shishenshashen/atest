# EA 必查清单（发版前 Checklist）

> **发版前**逐项打勾，缺一不可。

## 编译

- [ ] 0 编译错误
- [ ] 0 编译警告（重要警告）
- [ ] `OnInit` 返回 `INIT_SUCCEEDED`
- [ ] `OnDeinit` 释放所有资源（指标句柄 / 对象 / 文件 / 定时器）

## 参数

- [ ] Magic 唯一（不跟其他 EA 冲突）
- [ ] Comment 描述清楚
- [ ] 默认参数合理（手数 0.01、风险 1%、最大持仓 3）
- [ ] input 加了 `group` 分组
- [ ] 重要 input 加注释（行末 `// 注释`）

## 风控

- [ ] 下单前调 `Risk.CanOpen()`
- [ ] 紧急硬止损（净值跌破阈值全平）
- [ ] 单笔最大风险 1-2%
- [ ] 最大持仓数限制
- [ ] 手数规范化（min/max/step）
- [ ] 最小止损距离检查
- [ ] 资金/保证金检查

## OrderSend

- [ ] `type_filling` 正确（用 `GetFilling()` 自动选）
- [ ] 价格 `NormalizeDouble(price, _Digits)`
- [ ] 滑点 `deviation` 设置合理（5-30）
- [ ] 检查 `result.retcode == TRADE_RETCODE_DONE`
- [ ] 处理 retcode 10004/10020 重试
- [ ] `GetLastError()` 处理
- [ ] magic 字段填写

## 指标

- [ ] `OnInit` 创建句柄
- [ ] `OnDeinit` 调 `IndicatorRelease`
- [ ] 数组 `ArraySetAsSeries`
- [ ] 检查 `EMPTY_VALUE`

## 时间

- [ ] 用 `TimeCurrent()`（不是 `TimeLocal()`）
- [ ] 服务器时区记清楚
- [ ] 跨午夜时间窗口处理好（>0 表示跨日）
- [ ] K 线触发用 `iTime` 变化判断（新 K 线）

## 多品种

- [ ] `SymbolSelect` 加入 Market Watch
- [ ] 检查 `SymbolInfoInteger(SYMBOL_TRADE_MODE) != DISABLED`
- [ ] 各品种独立的 `SYMBOL_TRADE_TICK_SIZE/VALUE`
- [ ] 不在 OnTick 而在 OnTimer 处理其他品种

## 资源

- [ ] 定时器 `EventKillTimer()`
- [ ] 全局变量加前缀，`OnDeinit` 删除
- [ ] 文件 `FileClose`
- [ ] Comment "" 清理
- [ ] 对象按前缀清理

## 跨经纪商

- [ ] 不硬编码点差/合约/最小手数
- [ ] 用 `SymbolInfoDouble/Integer` 查
- [ ] 适配 `EURUSD`/`EURUSD.m` 等不同后缀
- [ ] 加点差过滤
- [ ] 适配不同 filling 模式

## 回测

- [ ] 数据时间至少 2-3 年
- [ ] 用 "每个报价基于真实 Tick" 模式
- [ ] 至少 30 笔交易
- [ ] Profit factor > 1.5
- [ ] Max drawdown < 20%
- [ ] 多组参数都测试（避免 overfitting）
- [ ] 多时间框架测试

## 模拟

- [ ] 模拟账户跑至少 1 周
- [ ] 信号触发正常
- [ ] 出场正常
- [ ] 资金/持仓面板显示正确
- [ ] 没有报错

## 实盘前

- [ ] 经纪商条款允许 EA
- [ ] 经纪商允许剥头皮（如有）
- [ ] VPS 选好（低延迟）
- [ ] 推送通知配置好
- [ ] 设了资金硬止损
- [ ] 设了最大单日亏损
- [ ] 准备手动接管方案

## 文档

- [ ] EA 顶部 #property description
- [ ] 关键函数加中文注释
- [ ] 参数用 input comment
- [ ] changelog 记录版本

## 监控（实盘后）

- [ ] MT5 Push 推送设好
- [ ] 邮件通知设好
- [ ] OnTimer 周期检查
- [ ] 异常告警机制
- [ ] 每日 1 次自动发心跳（确认 EA 还在跑）

## 日常维护

- [ ] 每周看一次回测 vs 实盘差异
- [ ] 每月看一次 max drawdown
- [ ] 每季度复盘交易记录
- [ ] 关键参数改一次要看一个月效果

## 上线 SOP（标准操作流程）

1. 复制 EA 到 `MQL5/Experts/`
2. MetaEditor 编译
3. 拖到模拟账户图表
4. 启用 "允许 EA 交易" 按钮
5. 观察 30 分钟看首次信号
6. 检查推送/邮件有没有报错
7. 检查日志（Experts 标签）
8. 跑 1 周后看实盘 vs 回测差异
9. 小资金上实盘（建议 1/10 目标资金）
10. 持续监控 1 个月后再加仓

## 反模式（永远不要做的 7 件事）

> 上面的 checklist 是"必查", 本节是"**绝对不能做**"——做完任何一件都可能导致 EA 静默失效 / 实盘亏钱 / 资源泄漏。

### 永远不要 1：忘了 `OnDeinit` 清理资源

```mql5
// ❌ 错：OnInit 创建的句柄 / 对象 / 文件 / 定时器没在 OnDeinit 释放
int g_atr_handle;
int OnInit() {
   g_atr_handle = iATR(_Symbol, PERIOD_CURRENT, 14);
   EventSetTimer(60);
   int h = FileOpen("log.txt", FILE_WRITE);
   return INIT_SUCCEEDED;
}
void OnDeinit(const int reason) {        // ❌ 空函数
   // ATR 句柄没 IndicatorRelease
   // 定时器没 EventKillTimer
   // 文件没 FileClose
}
```

**根因**：EA 卸载时漏清理 = **句柄泄漏 / 定时器残留 / 文件被锁**。下次加载 EA 报"handle already exists"或文件写不进去。**M16 Cleanup::CleanupAll(Magic, prefix, prefix, true, true, true) 一键搞定**（撤挂单 + 删本 EA 对象 + 清 GV + 清文件 + 杀定时器）。参考 [[实战/MeanReversion_EA 接入报告]] §2.1。

### 永远不要 2：把 SLTP 算进 PnL 但不考虑 commission

```mql5
// ❌ 错：显示 PnL = SLTP 价差, 忽略 commission
double pnl = (closePrice - openPrice) * lot * contractSize;
// ECN 经纪商 $3.5/手 commission, 1 周 100 笔 = $350, 直接吃掉盈利

// ✅ 对：PnL = 价差盈亏 - commission - swap
double commission = 0;
HistorySelect(startTime, TimeCurrent());
for (int i = 0; i < HistoryDealsTotal(); i++) {
   ulong ticket = HistoryDealGetTicket(i);
   commission += HistoryDealGetDouble(ticket, DEAL_COMMISSION);
}
```

**根因**：ECN 经纪商（Exness ECN / IC Markets Raw）$3-7/手 commission, 1 周 100 笔高频 = $300-700。**任何 PnL / Sharpe / 净盈利计算必须减 commission**。M11 logger.Trade 内置 commission 字段, 直接用 `DEAL_COMMISSION`。

### 永远不要 3：忘了给 EA 写 `#property description`

```mql5
// ❌ 错：EA 没有 description, 工具箱里看不出 EA 干什么
#property copyright "MyEA"
#property version   "1.00"
#property strict
// 缺 #property description

// ✅ 对：3 行 property 写清楚
#property copyright "MyEA"
#property version   "1.00"
#property strict
#property description "XAUUSDm H1 逆势均值回归 (BB+RSI)"
#property description "M01+M02+M03+M18+M19 模块, Magic=20260101"
#property description "2026-06-04 v1.5 release"
```

**根因**：MT5 工具箱右键 EA 看 "About" 标签只有 description 字段。**用户 1 个月后忘记 EA 干什么就看这里**。MQL5Kit 所有示例 EA 都带 3 行 description。

### 永远不要 4：直接调 `SymbolInfoTick` 不用 `CopyTicks`（5+ 倍延迟）

```mql5
// ❌ 错：每 tick 取最新价
MqlTick tick;
SymbolInfoTick(_Symbol, tick);        // 单次 ~0.1-0.3 ms, XAUUSDm M1 5+ tick/s = 1-2 ms/s
double bid = tick.bid;

// ✅ 对：用 M04 IndicatorPool 缓存 OR CopyTicksRange 批量拉
MqlTick ticks[];
int n = CopyTicks(_Symbol, ticks, COPY_TICKS_INFO, 100);  // 一次拉 100 条, 后续 0 IO
```

**根因**：`SymbolInfoTick` 每次走 MT5 internal 跨线程, 高频调用延迟 0.1-0.3 ms。**OnTick 100+ tick/s 累计 30+ ms/s = 拖慢 OnTick 主流程 30%**。**M04 IndicatorPool 已封装, 或者 OnInit 一次 `CopyTicksRange` 缓存最新 tick**。参考 [[实战/ScalperXAU 接入报告 + v1→v4 演进史]] v3→v4 优化（用 M13 CSV 缓存 5+ 倍加速）。

### 永远不要 5：在 `OnTick` 调 `FileOpen`（高频 IO 阻塞）

```mql5
// ❌ 错：OnTick 每 tick 写文件
void OnTick() {
   int h = FileOpen("trades.csv", FILE_WRITE | FILE_READ | FILE_CSV, ',');
   FileWrite(h, TimeCurrent(), price, lot);
   FileClose(h);                  // 每次都开文件, 慢且锁文件
}

// ✅ 对：M11 Logger 节流, OnTrade 触发写
int OnInit() { logger.Init("trades.csv"); return INIT_SUCCEEDED; }
void OnTrade() { logger.Trade(...); }  // M11 内部 100ms 节流 + Append 模式
```

**根因**：`FileOpen` 涉及 OS 文件锁, 单次 1-5 ms。**OnTick 高频 (5+ tick/s) = 25+ ms/s CPU 浪费 + 文件锁冲突**。**M11 logger.Trade 用 Append 模式 + OnTrade 触发, 一次写入批量 flush**。参考 [[实战/MeanReversion_EA 接入报告]] §2.1 M11 行。

### 永远不要 6：假设 `PositionsTotal() == 0` 等于"无持仓"

```mql5
// ❌ 错：多 EA 同 magic 同品种时误判
int total = PositionsTotal();
if (total == 0) {
   // 实际有 3 个其他 EA 的同品种单 (magic 相同), 但 total=0 只因当前 EA magic 不匹配
   OpenNew();                       // 又开 1 单, 仓位实际 4 单
}

// ✅ 对：CPositions::CountMine(Magic) 按 magic 过滤
int mine = CPositions::CountMine(Magic);
if (mine == 0) {
   OpenNew();
}
```

**根因**：`PositionsTotal()` 返回**整个账户**的持仓数, 不分 EA。**多 EA 同 magic 同品种时计数错位**。**M07 CPositions::CountMine(Magic) 按 magic + 品种过滤**, 任何"我有多少单"判断都用它。**M02 Risk::CanOpen 内部已用 CountMine, 调 M02 就避免这个问题**。

### 永远不要 7：跳过 `deviation` 容忍度（市价单全被拒）

```mql5
// ❌ 错：市价单用 deviation=0
req.deviation = 0;                  // 99% 拒单 (10020 PRICE_CHANGED)

// ✅ 对：剥头皮用 5-30, 趋势用 30-50
req.deviation = InpDeviation;       // input 默认 30 (XAUUSDm)
```

**根因**：`deviation = 0` = 经纪商要求"成交价 = 请求价到小数点最后一位", 实际行情每秒波动 1-3 点, 这个条件几乎不成立。**deviation 永远 > 0**: 剥头皮 5-10, 趋势 30-50。**M01 CTradePlus `trade.SetDeviation(30)` 一行设置**。参考 [[04-避坑与速查/02 OrderSend 错误码速查]] 反模式 2。

### 永远不要 8：忘了 `EventKillTimer`（OnDeinit 残留定时器 60s 持续触发）

```mql5
// ❌ 错：OnInit 设了定时器, OnDeinit 没杀
int OnInit() {
   EventSetTimer(60);                  // 1 分钟一次
   return INIT_SUCCEEDED;
}
void OnDeinit(const int reason) {     // ❌ 漏 EventKillTimer
   // 定时器残留, 卸载 EA 后 60 秒仍触发 OnTimer
}
```

**根因**：EA 卸载后定时器**不会自动停**, 仍按 60 秒周期调用 `OnTimer`。**EA 重新加载 = 多 1 个定时器并发 = 推送重复 / 写入重复 / CPU 多 1 个空转**。**M16 Cleanup::CleanupAll(Magic, prefix, prefix, true, true, true) 内置 `EventKillTimer()`, 任何用了 EventSetTimer 的 EA 必须在 OnDeinit 调**。参考 [[实战/MeanReversion_EA 接入报告]] §2.1 M16 行号（`OnDeinit` 调 `cleanup.CleanupAll(...)`）。

### 永远不要 9：忘了 `OnDeinit` 清理全局变量 (GV，跨重启读到过期 state)

```mql5
// ❌ 错：M12 GV 写入后 OnDeinit 不清
int OnInit() {
   GlobalVariableSet("MyEA_State_1", 1);  // 跨重启保存
   return INIT_SUCCEEDED;
}
void OnDeinit(const int reason) {     // ❌ 漏 GlobalVariableDel
   // 卸载后 GV 仍在, 1 个月后重新 attach EA = 读到 1 个月前的 state
}
```

**根因**：M12 GlobalVariable 是**MT5 全局命名空间**, 不带 EA 标识 = 多个 EA 可能同名冲突。**EA 卸载时不清 GV = 残留 1 个月前状态, 重新加载读到过期数据 → 误判**。**M16 Cleanup::CleanupAll(..., true) 内置 GV prefix 清理**。**所有 GV key 必须带 EA 名前缀**（如 `MyEA_State_1`, `MyEA_PositionCount`），卸载时按 prefix 全删。命名规范 `GlobalVariableDel("MyEA_*")` 用 wildcard 删除。

### 永远不要 10：把 SL/TP 价差当 PnL 但漏算 commission / swap（净利润虚高 50%+）

```mql5
// ❌ 错：PnL 只算 SLTP 价差, 漏 commission / swap
double pnl = (closePrice - openPrice) * lot * contractSize;  // 看着 +$50
// 实际: +$50 - $7 commission - $3 swap = $40, 1 周 100 笔 = 差 $1000
```

**根因**：M02 风控计算的 PnL 必须**减 commission / swap / rollover 三项**。**ECN 经纪商 $3.5-7/手 commission, 1 周 100 笔高频 = $350-700**, swap 隔夜 0.5-2 点/手, **3 倍 swap 周三扣 1.5-6 点**。**任何 PnL / Sharpe / 净盈利计算必须**：
```mql5
double pnl_total = grossPnl;
HistorySelect(startTime, TimeCurrent());
for (int i = 0; i < HistoryDealsTotal(); i++) {
   ulong ticket = HistoryDealGetTicket(i);
   pnl_total -= HistoryDealGetDouble(ticket, DEAL_COMMISSION);  // 减 commission
   pnl_total -= HistoryDealGetDouble(ticket, DEAL_SWAP);        // 减 swap
   pnl_total += HistoryDealGetDouble(ticket, DEAL_FEE);         // 减 fee
}
```

**M11 logger.Trade 内置 commission / swap 字段, 直接用 `DEAL_COMMISSION` / `DEAL_SWAP`**。任何 EA 自己写 PnL 不查这 3 字段 = 净利润虚高 50-100%。

### 永远不要 11：忘了给 EA 写 `#property description`（MT5 工具箱 "About" 标签空白）

```mql5
// ❌ 错：EA 顶部没写 description
#property copyright "MyEA"
#property version   "1.00"
#property strict
// 缺 #property description
// MT5 工具箱 → 右键 EA → "About" 标签空白
```

**根因**：MT5 工具箱右键 EA 看 "About" 标签只有 3 个字段：copyright / version / description。**description 缺 = 1 个月后忘记 EA 干什么**（"这 EA 是干什么的？我当时为什么写？"）。**正确 3 行 description**：
```mql5
#property copyright "MQL5Kit + YourName"
#property version   "1.50"
#property strict
#property description "XAUUSDm H1 逆势均值回归 (BB+RSI)"
#property description "M01+M02+M03+M18+M19 模块, Magic=20260101"
#property description "2026-06-04 v1.5 release"
```

**3 行 description = 写清楚: 品种+周期+策略+模块+版本**。MQL5Kit 所有示例 EA 都带 3 行 description（参 [[实战/MeanReversion_EA 接入报告]] §1.1 EA 头部 12 行）。

### 永远不要 12：上线忘备份源码到 `MQL5/Files/`（EA 丢失后无法重编译）

```mql5
// ❌ 错：实盘 EA 在 VPS 跑, 家里源码硬盘坏, 1 年后想改 EA = 找不到源码
//   → MetaEditor 打开的 .ex5 = 二进制, 无法反编译看 MQL5 源码
//   → 找 EA 作者 = EA 是自己写的, 作者也找不到原版
```

**根因**：MT5 `.ex5` 是编译后二进制, **不可反编译**（MQL5 官方保护）。**EA 上线前必须把 .mq5 源码备份到 3 处**：
1. `MQL5/Files/<EA>_v1.5_2026-06-04.mq5` (VPS 内, MetaTrader Files 目录)
2. 云盘（Google Drive / OneDrive / 坚果云）1 份
3. 本地 git repo 1 份（推荐 `EA-Backup/` 目录, 每次上线 commit）

**3 份备份 = EA 永远有源码**。**MQL5Kit 提供 `MQL5/Files/MQL5Kit_v2.0.zip` 完整源码包**, 任何 .ex5 丢失可重 unzip。VPS 重装系统 / 硬盘坏 = 1 份就够, **3 份保险**。

### 陷阱 5 条 (不与 80 baseline 16 err 重复, 5 段额外必查陷阱)

1. **OnDeinit 调 Cleanup 但忘 IndicatorRelease 指标句柄**:
   - ❌ 反例: `cleanup.CleanupAll(Magic, prefix, prefix, true, true, true)` 但 M04 IndicatorPool 的句柄没单独 IndicatorRelease
   - ✅ 正例: OnDeinit 先 `cleanup.CleanupAll(...)` 再 `IndicatorRelease(g_atr_handle); IndicatorRelease(g_rsi_handle);` (M04 内有 pool.ReleaseAll() 一键)
   - 根因: M16 Cleanup 主要清挂单/对象/GV/文件/定时器, 指标句柄需要单独调 M04 的 pool.ReleaseAll()

2. **PnL 计算 0 减 commission 但 M11 logger.Trade 已内置, 仍自己算**:
   - ❌ 反例: `double pnl = (close - open) * lot * contractSize;` 1 周 100 笔高频 = $350-700 commission 漏算
   - ✅ 正例: 用 M11 `logger.Trade` 写盘, 落盘字段含 DEAL_COMMISSION / DEAL_SWAP, PnL = price_diff - commission - swap
   - 根因: PnL 漏 commission = 净利润虚高 50-100%, 实盘打 7 折后仍亏

3. **SymbolInfoTick 高频 (5+ 倍延迟) 仍用未优化版**:
   - ❌ 反例: `MqlTick tick; SymbolInfoTick(_Symbol, tick);` OnTick 每 tick 调 = 5+ 倍延迟
   - ✅ 正例: OnInit 一次 `CopyTicksRange(_Symbol, ticks, COPY_TICKS_INFO, 100)` 缓存, OnTick 用缓存
   - 根因: SymbolInfoTick 跨 MT5 internal 线程, 单次 0.1-0.3 ms, OnTick 5+ tick/s 累计 30+ ms/s = 拖慢 OnTick 30%

4. **OnTick FileOpen 高频 IO (5+ 倍延迟) 仍用未优化版**:
   - ❌ 反例: `void OnTick() { int h = FileOpen("trades.csv", FILE_WRITE); FileWrite(h, ...); FileClose(h); }` 每 tick 开文件
   - ✅ 正例: M11 logger.Init() + OnTrade 触发 `logger.Trade(...)`, Append 模式 + 100ms 节流
   - 根因: FileOpen 涉及 OS 文件锁, 单次 1-5 ms, OnTick 5+ tick/s = 25+ ms/s CPU 浪费

5. **EA 跑 1 年 .ex5 丢失 (硬盘坏 / VPS 重装) 找不回源码**:
   - ❌ 反例: 上线 EA 后只在 VPS 跑, 家里硬盘坏 = 1 年后想改 EA = 找不到源码 (.ex5 不可反编译)
   - ✅ 正例: 1) `MQL5/Files/<EA>_v1.5_2026-06-04.mq5` VPS 内备份, 2) 云盘 1 份, 3) 本地 git repo 1 份
   - 根因: MT5 .ex5 是编译后二进制, MQL5 官方保护不可反编译, 3 份备份 = EA 永远有源码
