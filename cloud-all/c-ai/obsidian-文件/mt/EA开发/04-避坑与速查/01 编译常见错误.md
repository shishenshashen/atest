# 编译常见错误

> 编译 F7 后右下角"errors"标签里的错误。点错误跳到对应行。

## 错误速查表

| 错误 | 含义 | 解决 |
|---|---|---|
| `'{' - unexpected token` | 大括号不匹配 | 检查函数体 `{ }` |
| `';' - unexpected token` | 漏分号 | 行末加 `;` |
| `'X' - undeclared identifier` | 变量/函数没声明 | 拼写？忘了 include？ |
| `cannot convert enum` | 枚举类型不匹配 | 强转 `(ENUM_X)val` |
| `'X' - not a function` | 当函数用但它不是 | 看是不是拼错 |
| `'X' - parameter conversion` | 参数类型不匹配 | 强转 `int()`/`double()`/`string()` |
| `'X' - cannot open file` | include 找不到 | 路径错 → `MQL5\Include\` 下 |
| `'X' - redefinition` | 重复定义 | 检查 #include 多次 |
| `'X' - variable expected` | 期望是变量但给了字面量 | 改用变量 |
| `array out of range` | 数组越界 | 检查索引 |
| `zero divide` | 除数为 0 | 加 `if (div != 0)` 保护 |
| `array assignment not allowed` | 数组整体赋值 | 逐元素赋值或 `ArrayCopy` |

## 经典错误详解

### 1. `'X' - undeclared identifier`
```mql5
Print("hello");   // ❌ 忘了 #include <Trade/Trade.mqh>
```

解决：include 头文件。

### 2. `'X' - parameter conversion`
```mql5
int n = CopyClose(_Symbol, _Period, 0, 100, close);
//                                       ^^^^^^
//  'close' 必须是动态数组 double[]
double close[];   // ❌ 漏了
```

### 3. `'X' - cannot open file`
```mql5
#include <MQL5Kit/M01.mqh>   // ❌ MQL5\Include\MQL5Kit\M01.mqh 不存在
```
解决：把模块文件放到正确路径。

### 4. `'X' - not a function`
```mql5
double v = GetMAValue();   // ❌ 函数名写错，或没 include
```

### 5. `'X' - redefinition`
```mql5
input double Lot = 0.01;   // 重复定义：M01_CTradePlus.mqh 里也定义了 Lot
```
解决：换名字或 #include guard。

### 6. `'X' - cannot convert enum`
```mql5
ENUM_TRADE_REQUEST_ACTIONS a = 1;  // ❌ 1 是数字，不是 enum
ENUM_TRADE_REQUEST_ACTIONS a = (ENUM_TRADE_REQUEST_ACTIONS)1;  // ✅
```
**正确用法**：用 enum 常量名
```mql5
ENUM_TRADE_REQUEST_ACTIONS a = TRADE_ACTION_DEAL;  // ✅ 推荐
```

### 7. `'X' - variable expected`
```mql5
Buy(NULL, 0, 0, "");  // ❌ 第 2 个参数是 double，传了 0 没问题；但...
Buy(0.01, NULL, 0, "");  // ❌ 某些函数期望 string，传 NULL
```

### 8. `array out of range`
```mql5
double arr[10];
arr[10] = 0;  // ❌ 越界，合法索引是 0-9
```

### 9. `'X' - constant expected`
```mql5
input string Symbols = someVariable;  // ❌ input 必须是字面量
input string Symbols = "EURUSD,GBPUSD";  // ✅
```

### 10. `'X' - not all control paths return a value`
```mql5
int MyFunc(int n) {
   if (n > 0) return 1;
   // ❌ 漏了 n<=0 的返回
}
```

## 警告速查

| 警告 | 处理 |
|---|---|
| `'X' - return value expected` | 调用有返回值的函数但没用返回值 |
| `'X' - implicit conversion` | 隐式转换（int→double OK，double→int 危险）|
| `'X' - declared but not used` | 声明了但没用，可以忽略 |
| `'X' - possible loss of data` | 数据可能丢失（如 double → int）|

## 反模式（6 条不要做的事）

### 反模式 1：把 `extern` 误写成 `input`（EA 输入面板"消失"）

```mql5
// ❌ 错：编译 0 error, 但 EA 输入面板不显示参数
extern double Lot = 0.01;     // MQL5 已废弃 extern, 等同于"未声明"
input  double Lot = 0.01;     // ✅ MQL5 唯一合法写法
```

**根因**：MQL5 不支持 `extern`（MQL4 遗留），写了 `extern` MetaEditor 静默当 local 变量，**不显示在 EA 属性面板**。用户拖 EA 到图表看不到参数，以为 EA 没加载。**MQL5 永远用 `input` / `sinput` / `group`**。

### 反模式 2：跨文件 `const` 传参（编译过运行期崩）

```mql5
// header.mqh
class CFoo { public: int x; };
const int GLOBAL_X = 10;        // ❌ const 全局变量, EA 卸载后被释放

// EA.mq5
#include "header.mqh"
int OnInit() {
   Print(GLOBAL_X);              // 编译过, 运行期 GLOBAL_X 已释放 → 0/乱码
   return INIT_SUCCEEDED;
}
```

**根因**：MQL5 的 `const` 全局变量在 EA 卸载时回收。跨文件 const 引用是"看似全局实际局部"。**常量值用 `#define` 或 `enum`（编译期常量），不要用 `const` 跨文件传**。

### 反模式 3：全局对象声明顺序错（OnInit 抛 NULL）

```mql5
// ❌ 错：OnTick 用 ind, 但 OnInit 漏了 ind.Init
CIndicatorPool ind;            // 句柄未初始化 = INVALID_HANDLE
int OnInit() { return INIT_SUCCEEDED; }
void OnTick() {
   double rsi = ind.Value(_Symbol, PERIOD_M15, "RSI", 14);  // 句柄空 → 返回 0
   if (rsi > 70) { ... }        // 永远走错分支
}
```

**根因**：MQL5 不强制"声明 + 初始化"必须配对。编译 0 error, OnInit 跑过, OnTick 第一次调指标返回 0 / EMPTY_VALUE。**OnInit 必须给所有 object 调对应的 Init/Add, 任何漏调 = silent failure**。

### 反模式 4：`OnInit` 失败路径 `return 0` 而非 `INIT_FAILED`

```mql5
int OnInit() {
   if (SomeCheck() == false) {
      Print("初始化失败");
      return 0;                  // ❌ 返回 0 = 编译器警告 + MT5 仍认为 INIT_SUCCEEDED
   }
   return INIT_SUCCEEDED;
}
```

**根因**：MQL5 `OnInit` 必须返回 `INIT_SUCCEEDED` / `INIT_FAILED` / `INIT_PARAMETERS_INCOMPLETE` 三个 enum 之一。返回 0 = 强制转 `INIT_SUCCEEDED`，EA 仍会跑，但"实际初始化失败"信息被吞。**任何失败路径必须 `return INIT_FAILED;`**。

### 反模式 5：MQL5 编译过但 EA "不动"（99% 是 input 默认值 = 0）

```mql5
input int    InpPeriod = 0;     // ❌ 用户没在面板改, 默认 0 → OnTick 除零
input double InpRiskPct = 0;    // ❌ LotByRisk(0) = 0 手, EA "跑着但不开仓"
input bool   InpUseFilter = false;  // ❌ 用户以为 true, 默认 false → 过滤全程未启用
```

**根因**：MT5 不强制 input 默认值"安全"。EA 编译 0 error 跑起来, OnTick 一调 `LotByRisk(0) / 0` = 立即除零, EA journal 一片红但 expert 还在运行。**所有 input 必须给"业务合理默认值"（0 不是合理默认）**。

### 反模式 6：`Print` 每 tick 调（回测 10x 慢）

```mql5
void OnTick() {
   PrintFormat("OnTick %s price=%.5f spread=%d", _Symbol, Bid, Spread);
   // ❌ XAUUSDm M1 每秒 5+ tick = 5+ Print/秒, 回测 1 个月慢 10x
}
```

**根因**：`Print` 走 MT5 journal + 文件双写, 单次 ~0.1-0.5 ms。OnTick 高频 (5+/秒) 累计 0.5-2.5 ms/秒 = 25-50% CPU 浪费。**Print 必须用节流（60 秒一次）或只在 M10 异常触发**。参考 [[实战/BBTrendEA 复活 SOP]] §6 反模式 3。

### 反模式 7：include 头文件前未前置声明（编译 0 error，运行期 silent failure）

```mql5
// ❌ 错：include 头文件前没声明依赖的 class/enum
#include "MyUtils.mqh"           // 头文件内部用 class CFoo / enum EState
// ❌ 漏了 class CFoo; / enum EState; 前置声明
void OnTick() { ... }
```

**根因**：MQL5 的 `#include` 是**纯文本宏展开**（不是模块导入）。**头文件展开时如果找不到依赖的 class/enum/常量，编译 0 error, 但运行期头文件内的函数调用 silent failure**（返回 0 / 默认值 / 不报错）。**新 EA include 任何头文件前先 grep 头文件依赖的 class/enum/常量, 前置声明齐全再 include**。MQL5Kit 19 模块的 .mqh 已 `#include` 全部依赖, **直接用 M01 不用前置声明**, 自己写头文件才需要。

### 反模式 8：跨文件 `input` 与 `const` 同名（编译 redefinition 错）

```mql5
// header.mqh
const double g_lot = 0.01;         // 头文件里定义常量

// EA.mq5
input double g_lot = 0.01;         // ❌ EA 输入参数面板用同名 = 编译报 'g_lot - redefinition'
#include "header.mqh"
```

**根因**：`input` 是 EA 输入面板变量, `const` 是只读常量。**两者同名 = 编译报 `'X' - redefinition`**。**跨文件共享常量用 `#define MY_LOT 0.01`（编译期常量）或 `enum { LOT_MIN=1 }`（类型安全），永远不要 input + const 同名**。MQL5Kit 19 模块统一 `#define` 宏, EA 顶层用 `input` 但不与模块宏冲突。

### 反模式 9：return 路径不全（编译 0 error, 运行期返回栈剩余值）

```mql5
int GetSignal() {
   if (IsBuy()) return 1;
   if (IsSell()) return -1;
   // ❌ 漏了"无信号"路径 → IDE 弹 'not all control paths return a value' 警告
   //   MT5 编译 0 error (warn 静默), 运行期 GetSignal() 返回 0 (栈剩余值)
}
// 调用方误判：if (GetSignal() == 1) { 实际 GetSignal() 永远 == 0 }
```

**根因**：MT5 编译 0 error 但 IDE 弹警告 `'not all control paths return a value'`。**警告不是错误 = 编译过 = 编译期 0 errors**。**运行期函数返回 0**（栈上的"剩余值"），调用方当 0 = 误判信号方向。**任何带 `return X` 的函数, 末尾必须显式 `return 0` 或 `return INIT_SUCCEEDED` 占位**。`OnInit` 同理：失败路径必须 `return INIT_FAILED;`，不能 `return 0;`（参考 反模式 4）。

### 反模式 10：忘 `#include "MQL5Kit\\M17_NewsFilter.mqh"`（编译 'news' undeclared identifier）

```mql5
// ❌ 错：调 news.IsNearEvent() 但没 include M17
void OnTick() {
   if (news.IsNearEvent(30, 30, _Symbol)) return;  // ❌ 编译报 'news' - undeclared identifier
}
```

**根因**：MQL5Kit 19 模块是**独立 .mqh 文件**（每个 M0X 1 个文件）。**用哪个模块必须 `#include <MQL5Kit/MXX_Name.mqh>`**。**M17 NewsFilter / M18 CorrelationFilter / M19 SessionFilter 等"业务模块"必须显式 include**, 不像 `#include <Trade/Trade.mqh>` 那样"MT5 自带"。**EA 顶部 #include 区按 M01 → M19 顺序排列, 用 1 个加 1 个, 不要一次全 include**（避免单 EA 依赖 19 模块, 编译慢 + 维护难）。M01 必 include, 其他按需。

### 反模式 11：MQL5Kit 多副本路径混乱（编译 'cannot open file'）

```mql5
// ❌ 错：3 个 MQL5Kit 副本同时存在, 编译路径混乱
//   MQL5/Include/MQL5Kit/M01.mqh           (v1.0 旧版)
//   MQL5/Include/MQL5Kit_v2/M01.mqh        (v1.1)
//   MQL5/Include/MQL5Kit_v3/M01.mqh        (v2.0 最新版)
// EA: #include <MQL5Kit/M01.mqh>            // ❌ 找到 v1.0 旧版（编译 0 error 但行为与文档不符）
```

**根因**：MQL5Kit 分叉到多副本（v1 / v2 / v3）时, 编译路径混乱。**保留 1 个副本（最新版本）放 `MQL5/Include/MQL5Kit/`, 其他副本移到 `MQL5/Include/_archive/MQL5Kit_v1/` 或删除**。**编译前 `Get-ChildItem MQL5/Include/MQL5Kit* -Recurse` 应只看到 1 个有效目录**。MQL5Kit 编译验证脚本（`compile_test.bat`）开篇会检查 1 副本约束, 3 副本 = 编译报版本不匹配警告。

### 陷阱 5 条 (不与 80 baseline 26 err 重复, 5 段额外编译陷阱)

1. **MetaEditor 旧版缓存编译过 .ex5 (编译过但实际错)**:
   - ❌ 反例: 改完 .mq5 直接 F7, MetaEditor 静默"编译过"但实际用旧 .ex5 → 调试期"EA 跑老逻辑"
   - ✅ 正例: 改完 .mq5 → 手动 Project → Clean (删 .ex5 缓存) → F7 重编译 → 0 error + 0 warning + mtime 已更新
   - 根因: MetaEditor 默认 incremental compile, 大文件改完偶尔跳错. ex5 缓存 = 编译过但 .ex5 旧

2. **input group 顺序错导致 input 参数面板错位**:
   - ❌ 反例: L31 `input group "=== 仓位 ==="` 写在 L40 (在 L31-39 三个 input 之后), 前 3 个 input 不在 group 内 → 面板"3 杂项 + 仓位"乱排
   - ✅ 正例: `input group` 写在它管辖的 input 之前, 1 个 group 配 N 个 input, 严格顺序对齐
   - 根因: MetaEditor 把 group 之前未分组 input 归为 "General" 组, 之后 input 归对应 group

3. **OrderSend / OrderCalcMargin / HistorySelect 编译过但运行期 10021 SYMBOL_NOT_FOUND**:
   - ❌ 反例: 硬编码 `SymbolInfoDouble("XAUUSD", ...)` 在 Exness demo = 10021 拒单 (Exness 实际叫 "XAUUSDm")
   - ✅ 正例: 用 `Symbol()` (当前图表 symbol) 或 `SymbolExist()` 探测 "XAUUSD" / "XAUUSDm" / "XAUUSD.m"
   - 根因: 编译 0 error (SymbolInfoDouble 接受任意 string), 运行期经纪商 10021 拒

4. **EA 编译过但 MetaTrader 启动时不显示在 "Expert Advisors" 列表**:
   - ❌ 反例: EA 文件放 `MQL5/Experts/_test/MyEA.mq5` 子目录 → MetaTrader 启动不索引子目录 → 拖到图表报 "EA not found"

   - 根因: MetaTrader 启动时只索引 `MQL5/Experts/*.mq5` 根目录, 子目录要手动 Refresh
