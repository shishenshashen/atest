# M08 升级与迁移

## 升级前必做

```powershell
# 1. 备份配置 + memory + session
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
$backup = "C:\Users\Administrator\.mavis-backup\$ts"
New-Item -ItemType Directory -Force -Path $backup | Out-Null

# 必备份目录
@(
  "$env:USERPROFILE\.mavis\config",
  "$env:USERPROFILE\.mavis\memory",
  "$env:USERPROFILE\.mavis\agents",
  "$env:USERPROFILE\.mavis\im",
  "$env:USERPROFILE\.mavis\hooks"
) | ForEach-Object {
  if (Test-Path $_) {
    Copy-Item $_ "$backup\$((Split-Path $_ -Leaf))" -Recurse -Force
  }
}

# 2. 看当前版本
mavis --version
mavis config get version

# 3. 看升级说明（如果有 release notes）
mavis upgrade --notes
```

## 升级流程

```powershell
# 1. 停 daemon
mavis daemon stop

# 2. 升级 CLI
#    方式 A：官方安装器（推荐）
mavis upgrade

#    方式 B：手动下二进制替换
#    下载新版本 → 覆盖 mavis.exe

# 3. 检查新版本兼容
mavis doctor            # 自检工具

# 4. 启动 daemon
mavis daemon start

# 5. 验证
mavis --version
mavis session list      # 确认 session 注册表还在
```

## 数据目录（要备份什么）

| 路径                                            | 内容              | 升级是否保留 |
| --------------------------------------------- | --------------- | ------ |
| `~/.mavis/config/`                            | daemon / agent 配置 | 保留     |
| `~/.mavis/memory/`                            | user memory     | 保留     |
| `~/.mavis/agents/<name>/memory/MEMORY.md`     | agent memory    | 保留     |
| `~/.mavis/agents/<name>/workspace/`           | agent 工作区       | 保留     |
| `~/.mavis/sessions/`                          | session 状态      | 视实现    |
| `~/.mavis/hooks/`                             | hook 配置         | 保留     |
| `~/.mavis/im/`                                | IM 桥接配置         | 保留     |
| `~/.mavis/logs/`                              | 日志（可清）          | 不备份    |

## 跨机器迁移

把整套 `~/.mavis/` 拷过去即可——**但** 注意：

1. **路径差异**：daemon 配置里若有绝对路径，迁移后要改：
   ```bash
   mavis config list | grep -i path
   # 把所有 /home/user/.mavis 改成新机器的路径
   ```

2. **环境变量**：
   - `MAVIS_PORT` — 跨机器可能要重设
   - `MAVIS_WORKSPACE` — 同上

3. **CU 状态**：`beta.cuMode` 是按机器持久的，换机器后要重新开

4. **Agent 注册表**：agent 配置文件里有 `workspace` 字段，写死了路径，**必须改**

5. **凭证**：
   - 飞书 / TG 的 token 不在 `~/.mavis/`，在 lark-cli 配置里（`~/.lark-cli/`）和 TG 是环境变量
   - 单独备份这两块

## 升级常见不兼容点

| 版本变化        | 可能影响                              | 应对                           |
| ----------- | --------------------------------- | ---------------------------- |
| 0.x → 1.0   | 配置 schema 大改；agent 名空间重排         | 读 `mavis upgrade --notes`    |
| 0.5 → 0.6   | `mavis api` 路径前缀 `/api/` → `/mavis/api/` | 批量替换脚本里的 URL                |
| 0.6 → 0.7   | Hook 改用 JSON 5（新支持注释）             | 旧 hook 文件需迁移               |
| 0.7 → 0.8   | Memory 文件格式变化（YAML frontmatter 校验） | `mavis memory migrate` 自动转   |
| 任一 minor   | 新 MCP server 可能要求额外 auth          | 看 `mavis mcp ls`            |

## 回滚

```powershell
# 1. 停 daemon
mavis daemon stop

# 2. 恢复备份
Copy-Item "C:\Users\Administrator\.mavis-backup\<ts>\config" `
  "$env:USERPROFILE\.mavis\config" -Recurse -Force

# 3. 装回旧版本
# 把旧 mavis.exe 覆盖回去

# 4. 启动
mavis daemon start
mavis --version
```

## 大版本升级 checklist

- [ ] 备份 `~/.mavis/{config,memory,agents,hooks,im}`
- [ ] 读 release notes，找 "BREAKING" 段
- [ ] 在测试机器上先升一次
- [ ] 看 `mavis doctor` 输出，处理 warning
- [ ] 跑核心 agent：发 hello / 跑 cron / 调一次 IM
- [ ] 升级后 24h 监控 daemon 日志（异常率、OOM、启动失败）
- [ ] 保留旧 binary + 旧备份至少 30 天

## 升级失败应急

- **Daemon 起不来**：先看 `~/.mavis/logs/daemon.log` 启动栈
- **Session 列表全空**：注册表没持久化是正常；配置 / memory 在就行
- **Agent 找不到**：检查 `~/.mavis/agents/<name>/config.json` 还在
- **CU 状态丢了**：重新 `mavis config set beta.cuMode true` + PUT API

## 永不升级的场景

> ⚠️ 仅在你完全清楚后果时选择

- 跑关键交易 EA 在生产盘上，升级会引入未知 bug → 等 1~2 个 patch 再说
- 团队代码依赖某个 daemon API 行为，新版改语义了 → fork / 锁版本
- 网络环境无法验证新版（公司代理 / 离线） → 离线下载 binary 后再升
