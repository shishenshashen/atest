# 架构总览

## 三层关系

```
┌──────────────────────────────────────────────────────┐
│  Renderer（Electron 桌面 / Web 控制台）              │
│  - 用户界面、CU 渲染、消息推送                         │
│  - 内存里维护 CU enabled / disabled 状态              │
└───────────────────┬──────────────────────────────────┘
                    │ HTTP / WebSocket
                    │  PUT /mavis/api/cu/enabled
                    ▼
┌──────────────────────────────────────────────────────┐
│  Daemon（Node.js, 端口 15321）                       │
│  - agent runtime / session 管理 / MCP 路由 / API     │
│  - 内存状态：CU enabled、agent 注册表、cron 列表        │
└───────────────────┬──────────────────────────────────┘
                    │ local IPC / HTTP
                    ▼
┌──────────────────────────────────────────────────────┐
│  Agent 进程（worker / orchestrator）                 │
│  - 读 MEMORY.md、调 MCP 工具、写文件                   │
│  - 一个 agent 一次只跑一个 session tree                │
└──────────────────────────────────────────────────────┘
```

## 关键事实

1. **CU 状态有 2 处**：
   - **持久化**：`mavis config set beta.cuMode true`（写盘）
   - **运行时**：daemon 内存里的 `cu.enabled`（被 renderer 通过 API 翻转）
   - **改前者不会立即翻后者**——必须 PUT `/mavis/api/cu/enabled`。

2. **Renderer 是个叛徒**：
   - 任何窗口 `minimize` / `restore` 事件都可能 PUT `enabled=false`。
   - 日志：`[cu] enabled changed: true -> false`（daemon 端可见）。
   - 解法：keep-alive 脚本每 30s PUT `enabled=true`。

3. **Agent 内存 vs 磁盘**：
   - Daemon 重启 → 内存清空
   - 配置、agent 注册、memory 文件 → 磁盘持久化
   - Session 列表 → daemon 内存（重启丢）

4. **路径前缀**：`/mavis/...`（不是 `/api/...`）。见 [[04-踩坑速查表/01 CU 相关踩坑]]。

## 启动顺序

```
mavis daemon start
   ↓
   初始化 MCP servers、agent registry、cron timer
   ↓
   监听 15321
   ↓
Renderer 启动
   ↓
   检测 daemon 状态 → 拉取 agent 列表
   ↓
   用户点击「打开 CU」→ PUT /mavis/api/cu/enabled {true}
   ↓
   Daemon 内存里 cu.enabled = true
   ↓
   加载 nut.js binding → 截屏/输入就绪
```

## 故障定位优先级

1. 端口 15321 能连吗？ → `Test-NetConnection`
2. Daemon 进程在吗？ → `Get-Process -Name mavis`
3. CU enabled？ → `GET /mavis/api/cu/enabled`
4. Console session 吗？ → `qwinsta` 查看当前 session
5. Keep-alive 脚本在跑吗？ → `Get-Process -Name powershell` 找守护进程
